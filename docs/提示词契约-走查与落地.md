## §1 一句话：面板改的不是副本。

面板写的就是 `build_messages()` 下一次要读的那个对象，**中间没有副本、没有缓存、不用 reload**：

```
模块级常量（agents.py / summarize.py，如 SYSTEM_TEMPLATE agents.py:770、summarize.PROMPT summarize.py:28）
  → 登记在 PROMPT_STATIC / PROMPT_TABLES / PROMPT_JSON_TABLES（admin_api.py:72 / :134 / :152）
     不登记：面板看不见 + tests/_smoke-admin.py:224 守门红
  → GET /api/admin/prompts 按当前代码现算、动态展开（_catalog() admin_api.py:377；路由 admin_api.py:523）
  → POST 保存：_write_path()（admin_api.py:414）顶层 setattr（admin_api.py:420）、表内原地改字典（admin_api.py:425）
  → build_messages() 每次模型调用实时读这些属性（agents.py:1168；SYSTEM_TEMPLATE.format 在 agents.py:1187）
  → 该次调用全文落 runs/<日期时间>_<局号>_v<短哈希>/trace.jsonl 的 prompt_system / prompt_user（run_archive.py:221）
```

关键点：`_write_path` 改的是**模块属性本身**（`setattr(mod, ...)` admin_api.py:420），
而 `build_messages` 读的也是这个模块属性 —— 所以"改副本"这件事在结构上不可能发生。

## §2 第②列怎么用。

**三种条目，改了都立刻生效**（差异只在存法和能不能加删）：

| 条目 | 存法 | 加/删 | 生效 |
|---|---|---|---|
| STATIC 模块级字符串 | 顶层 `setattr`（admin_api.py:420） | 只能改文本，加项要改代码 | 下一次模型调用，含进行中的局 |
| TABLE 表里的叶子 | 原地改字典（admin_api.py:425） | 叶子不能加删，加/删走下面的整表 | 同上 |
| JSON 整张表 | 整表替换，先过「字符串→字符串」JSON 校验（admin_api.py:594-606） | **只有这两张能加删** | 同上 |

- **能加/删条目的只有两张表**：`TASKS`、`VOICE_BY_PERSONALITY`（`PROMPT_JSON_TABLES` admin_api.py:152）。
- `PERSONALITIES`（性格 9 条 → 18 项）、`LEVELS`（档位/赌注 4 档 → 8 项）、`PRIVATE_LINES`（身份私有句 35 条）
  **只能改叶子文本，不能加项**（admin_api.py:134-150）；加一项必须改代码 + 登记，否则面板上根本不出现。
- **只读区 8 条**（`PROMPT_READONLY` admin_api.py:155-164），挑三条讲为什么：
  `LEAK_PATTERNS`（admin_api.py:156）是可改就等于拆守卫；`_CONTROL_KEYS`（admin_api.py:158）是解析协议、不是 prompt；
  `_GOD_SHORT`（admin_api.py:162）只是界面显示。
- **函数体内 9 条**（`PROMPT_FUNC_LITERALS` admin_api.py:171-193）的存在理由：守门会扫函数体
  （tests/_smoke-admin.py:271），**≥30 字**的句子不登记就报红（tests/_smoke-admin.py:292）。
- 面板 `count` 就是可改项数（admin_api.py:562 = `len(_catalog())`），条目按 `group` 分组渲染（admin_api.py:528-535）。

## §4 生效语义与五个坑。

1. **提示词**：下一次模型调用就生效，**含进行中的局**（接口 note admin_api.py:563-565、返回 note admin_api.py:620）。
   要只影响新局，等没人玩时保存。
2. **`_runtime.json` 优先级高于代码**：`apply_runtime_state()`（admin_api.py:211）在 `build_pipeline()` **之前**跑
   （server.py:143），重启后照样盖住 `agents.py`。改代码不等于改线上。
3. **没有"恢复默认"接口**：可写的只有 `POST /api/admin/prompts`（admin_api.py:568），没有 reset、没有删除；
   `_catalog()` 只算条目、不比对代码默认值（admin_api.py:377-404），所以"与代码不一致"不会告警 —— 改回去只能手动再填一次。
4. **离线沙盒与线上不同源**：实验室单步重跑走一次性覆盖 `consume_override()`（agents.py:1325），
   整体替换 system/user（agents.py:1332-1336），不写契约、不落盘；草稿定稿必须抄进第②列。
5. **推了席位覆盖后，`/play` 封面填的 LLM key 不再用于对局**（ASR/TTS 不受影响）：
   `_lab_override_active()`（admin_api.py:299）+ 应答里的提示（admin_api.py:351-353）。

## §5 出问题时的判别法则（给她的一句话）。

打开那次调用的 `runs/<...>/trace.jsonl` 看一行（写入点 run_archive.py:221，追加 run_archive.py:240）：
- `prompt_system` / `prompt_user` 里**有她改的文本** → 后端没吃错，问题在措辞或模型，**归她**；
- **没有**（或整段缺失） → 接口/装配问题，**找后端**。

## §6 冻结落地 runbook：第②列 → 代码常量。

**为什么必须做**：`.gitignore` 第 8 行就是 `_runtime.json`（`.gitignore:8`），所以**面板上保存的每一版 prompt 永不进 git**。
评委机 / 录屏机 / 换目录跑，跑出来的都是旧文本 —— 只有代码常量会跟着仓库走。

四步（11/3 收工时执行）：
1. `GET /api/admin/prompts` 导出全部条目全文（现在 116 项）。
2. 按 `key`（形如 `agents:SYSTEM_TEMPLATE`）逐条贴回 `agents.py` / `summarize.py` 的模块常量。
3. 删掉 `_runtime.json` 的 `prompts` 段（**只删这一段，`env` 段保留**——那里是 key/通道），重启服务。
   文件在**仓库根**：`STATE_PATH = base / STATE_NAME`（admin_api.py:218），`base` 是服务端传进来的 `ROOT`
   （server.py:39-40），不是 `backend/`。
4. 再 `GET /api/admin/prompts`，逐条确认"面板值 == 代码值"，把当次 `git rev-parse --short HEAD` 记进 `runs/`。

**代码常量是唯一真相，`_runtime.json` 只是草稿本。**
